# Country Localization Standard

Poland is the current localization baseline for mature Country Hubs.

When a future AI agent is asked to localize a country, it must use Poland as the reference for completeness, not only for visual structure. A localized country page must feel intentionally written in the selected language, not like an English page with translated navigation.

## Supported Locales

Current ValidoHub localized routes are:

- English: `/en/`
- Polish: `/pl/`
- German: `/de/`
- Spanish: `/es/`
- Brazilian Portuguese: `/pt-BR/`

A country is not localization-complete until every supported non-English locale has been checked.

## What Must Be Localized

For each country page, localize all visible user-facing copy:

- Header navigation and language selector labels.
- Breadcrumb labels where they are human-readable.
- Hero eyebrow, title pattern, summary, badges, and search UI.
- Country visual captions and card labels.
- Quick-copy labels, copy button text, and copy labels.
- Workbench catalog headings, group descriptions, tool descriptions, tags, statuses, and empty states.
- Identity, locale, technical, address, phone, vehicle, administrative, tax, banking, payment, official-source, ecosystem, and knowledge-graph sections.
- Card descriptions, helper captions, reference notes, badges, and chips.
- Documentation summaries and accordion labels.
- Error/empty/match-count text generated by country-page JavaScript.

The Polish country page is the acceptance benchmark for this coverage.

## What Must Not Be Blindly Localized

Preserve technical meaning and routing stability:

- Do not translate URLs, canonical links, route slugs, hreflang URLs, asset paths, CSS classes, JavaScript selectors, or data keys.
- Do not translate official acronyms such as PESEL, NIP, REGON, KRS, IBAN, BIC, SEPA, KSeF, JPK, BDO, CEIDG, TERYT, SIMC, ULIC, CEPiK, UFG, EORI, VAT, PLN, ISO, TLD, XML, JSON, or API.
- Do not translate official product or authority names unless the localized language has a conventional display name. Prefer keeping the official local name and translating the explanatory sentence around it.
- Do not run broad replacements such as replacing every occurrence of `Polish`, `address`, `tax`, or `Right` globally. These can corrupt prose, routes, classes, and data attributes.
- Do not translate real code snippets by default. Only localize protected code/pre blocks when they are visible country facts or sample addresses and the replacement is exact and safe.

## Implementation Rules

Localization may be implemented through source data, renderer strings, or the final localization pass, but the result must be deterministic and safe.

Use exact-string maps for rich country page copy. Use text-only replacements for short labels and chips so replacements happen only in visible text nodes or safe `data-copy-label` attributes.

If a new section is added to the Poland-style Country Hub, add its localization strings for every supported locale in the same change. Never ship an English-only rich section on a localized page.

If a new country becomes Poland-grade, add localized country names, local values, official-source explanations, address examples, search labels, and all section copy for every supported locale before calling the country done.

## Verification Checklist

Before committing localization work:

1. Run syntax checks for changed JavaScript files.
2. Run the normal ValidoHub build/publish pipeline.
3. Run Engine doctor for ValidoHub when content or route behavior changed.
4. Inspect generated pages for each supported locale.
5. Grep generated localized country pages for known English leftovers from the edited sections.
6. Confirm localized pages do not expose `quality 40%` or English `/en/...` user-facing route text; hreflang alternates may still reference `/en/...`.
7. Confirm generated output is not staged or committed.
8. Confirm Valido Engine remains untouched unless the user explicitly approved a generic platform change.

## Future-Country Shortcut

When a user says, "make Germany like Poland" or "make another country like Poland", interpret that as:

- Reuse Poland's mature Country Hub structure and quality bar.
- Build country-specific tools and references, not copied Polish content.
- Localize the country to every supported locale using this document.
- Keep all product behavior and localization ownership in ValidoHub.
- Do not modify Valido Engine for country-specific localization.
