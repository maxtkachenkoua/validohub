# Poland Country Hub Gold Standard

Poland is the canonical reference for mature, tool-rich Country Hubs in ValidoHub.

When a future AI agent is asked to "make another country like Poland", this document is the required implementation standard.

Brazil remains the original country-hub template reference for the base visual system and country metadata architecture. Poland is the higher bar for a full developer portal with many workbenches, deep local standards, rich cross-linking, search, reference ecosystems, and premium country-specific UX.

## Core Rule

A mature Country Hub must feel like a complete developer portal for that country, not a list of validators.

Poland demonstrates the target level of:

- Tool density.
- Country-specific usefulness.
- Premium visual hierarchy.
- Workbench discoverability.
- Internal linking.
- Reference metadata.
- Available and planned tool clarity.
- Developer-first copy.
- Local standards coverage.

Do not copy Polish content into another country. Copy the structure, quality bar, section strategy, and linking behavior.

## Page-Level Standard

A Poland-grade country page must include, where locally relevant:

1. Premium country hero with flag-aware visual tone.
2. Country shape and location visual cards.
3. Compact country tool search near the hero.
4. Copy-ready developer values.
5. Available workbench catalog grouped by user intent.
6. Planned/future workbenches clearly marked without pretending they work.
7. National identifier standards.
8. Banking standards.
9. Payment networks.
10. Address and locale standards.
11. Government and registry ecosystem.
12. Official sources and reference portals.
13. Knowledge graph / relationship metadata.
14. Developer snippets or constants where useful.
15. Cross-links from the country hub to every available country workbench.
16. Cross-links from each country workbench back to the country hub.

The page should put useful actions and discovery before long explanatory documentation.

## Tool Portfolio Standard

A mature country should not stop at one famous identifier.

Build a country-specific tool portfolio across these categories when locally relevant:

- Personal identifiers.
- Tax identifiers.
- Business registries.
- Banking account formats.
- Payment systems.
- Invoice and tax documents.
- Address and postal formats.
- Phone numbers.
- Vehicle and transport identifiers.
- Insurance and healthcare identifiers.
- Government classification codes.
- Locale, date, currency, and amount formats.
- Privacy, masking, and test-data workflows.
- Developer data quality tools.

Every available tool must have a real workbench or useful browser-side behavior. Do not mark a tool available if it is only an idea.

## Localization Standard

A Poland-grade country is not complete if only the English page is polished.

The country page, available tool catalog, official-source cards, identity facts, locale facts, address examples, copy controls, tags, badges, helper captions, and generated JavaScript UI must be localized for every supported ValidoHub locale. Use `docs/product/COUNTRY_LOCALIZATION_STANDARD.md` as the canonical checklist.

For future countries, Poland is the localization acceptance benchmark: copy the completeness standard, not the Polish text.

## Workbench Quality Standard

Country workbenches should follow the PESEL-quality bar and the Poland suite visual system.

Each premium country workbench should provide as many of these as the domain supports:

- Validate.
- Normalize.
- Explain structure.
- Show check digits or algorithm steps.
- Generate safe fictional fixtures.
- Batch-check where useful.
- Mask or redact sensitive values.
- Copy normalized value.
- Download result.
- Show diagnostics with exact failing step.
- Provide debugger / calculation breakdown.
- Provide advanced analysis.
- Provide developer JSON or API preview.
- Explain offline limits clearly.
- Never pretend to perform live government or bank lookups.

A tool should be better than common online competitors for its specific format, not merely present.

## Section Ordering

Use this order for a mature Poland-style country page unless there is a strong product reason to adjust:

1. Hero with search and geographic identity.
2. Developer quick actions / copy values.
3. Available workbench catalog.
4. Featured or most important national identifiers.
5. Banking and payment standards.
6. Address, phone, locale, and data-format standards.
7. Government registry ecosystem.
8. Official sources.
9. Knowledge graph and relationship metadata.
10. Planned workbenches / roadmap-style discovery.
11. Deep documentation and reference notes.

Do not bury available tools below long documentation.

## Catalog Grouping Rules

Large country catalogs must be grouped by intent, not dumped as one flat grid.

Use groups such as:

- Identity & government.
- Tax & business.
- Banking & payments.
- Invoices & accounting.
- Address & postal.
- Phone & telecom.
- Vehicle & transport.
- Data quality & privacy.
- Locale & formatting.

Groups should be expandable or scan-friendly. A country with 30-50+ entries must remain easy to navigate.

## Search Rules

A mature country page should include a compact country tool search near the hero when the catalog is large.

Search must:

- Filter available/planned workbench rows.
- Match local names, English names, acronyms, and common user phrases.
- Open matching groups automatically.
- Show a compact match count.
- Avoid horizontal overflow.
- Work on mobile.
- Not replace the full catalog; it is a fast path.

## Linking Rules

Country pages must be internally connected.

For every available country-specific tool:

- The country hub must link to the tool page.
- The tool page must link back to the country hub where the renderer supports it.
- Related tools should be cross-linked by category, country, and use case.
- Planned entries must not link to nonexistent pages unless a valid metadata-only page exists.
- Cards must visually distinguish available, ready, planned, experimental, and reference-only entries.

Avoid fake buttons. If something is not clickable, it should read like reference information, not like a disabled action.

## Reference and Source Rules

Official sources and registry cards should be useful, but not misleading.

For each source card, clarify whether it is:

- Official lookup.
- Official specification.
- Reference portal.
- Legal/regulatory context.
- Label-only source included for developer orientation.

If a card has no link, do not style it as an interactive link.

## Visual Standard

Poland is the visual target for mature country pages:

- Flag-aware hero gradient.
- Compact search in the hero.
- Premium card spacing.
- Strong but calm typography.
- Consistent badge system.
- No random emoji decoration in new UI.
- No empty blocks.
- No generic copy reused across unrelated tools.
- Long values must wrap safely.
- Desktop and mobile must have no horizontal overflow.

Each country may have its own visual identity through flag colors, local geography, official marks, and local standards. Do not make every country visually identical.

## Copywriting Standard

Country copy must be specific to that country.

Avoid generic sentences such as:

- "Validate data locally with PESEL-grade diagnostics."
- "Local sandbox, batch mode, masking, audit JSON, no lookup" repeated everywhere.
- Reused documentation section titles that reveal file names instead of user meaning.

Use domain-specific language:

- What the format is.
- Who uses it.
- What can be validated offline.
- What cannot be verified without an official lookup.
- What developers usually get wrong.
- What systems it connects to.

## Done Criteria For A Poland-Grade Country

A country can be considered Poland-grade only when:

- It has a rich country page with no empty or fake sections.
- Its available tools are linked and genuinely usable.
- Planned items are clearly marked and not misleading.
- The page includes country tool search if the catalog is large.
- The tool catalog is grouped by intent.
- Official/reference sections are clear and non-fake.
- Desktop and mobile layouts are verified.
- Browser console has no errors.
- Generated output is not committed.
- Valido Engine remains untouched unless a generic platform change is explicitly required.

## AI Prompt Shortcut

When a future user says:

> Make [Country] like Poland.

Interpret it as:

1. Use Poland as the gold-standard mature Country Hub reference.
2. Build a country-specific tool portfolio, not a single page.
3. Create premium workbenches only where they can be genuinely useful.
4. Link available tools from the country hub.
5. Use planned/reference states honestly.
6. Keep all product assets and behavior in ValidoHub.
7. Do not modify Valido Engine for country-specific behavior.
