# Tool Page UX

Tool pages must be designed around task completion.

## Required Page Order

1. Header
2. Breadcrumbs
3. Tool title
4. Short description
5. Interactive workbench
6. Documentation
7. Related tools
8. Footer

The workbench must appear before documentation. Users should not need to scroll before using the primary tool.

## Workbench Requirements

- Primary input and output must be obvious.
- Actions must be clear, working, and keyboard-accessible.
- The active action should be visually clear when a tool has multiple modes.
- Copy and download should be available whenever output exists.
- Errors should appear near the workbench, not hidden in documentation.
- Examples should fill realistic sample input and run the appropriate action.
- Advanced details should be compact and collapsible where possible.

## Documentation Role

Documentation supports the task after the user has access to the tool.

Use documentation for:

- Explanation
- Examples
- FAQ
- References
- Developer examples

Documentation should not push the workbench below the first useful viewport.

## Mobile Requirements

- No horizontal scrolling.
- Buttons stack cleanly.
- Textareas remain comfortable.
- Advanced panels remain readable.
- Tool controls must still be usable with touch.

## Related Tools

Related tools belong after the documentation. Do not use a right sidebar for related links on tool pages.
